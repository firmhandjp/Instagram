# Instagram AIニュース自動投稿 設計書

作成日: 2026-11-08
状態: ユーザーの確認待ち

## 1. 目的と成功条件

- **目的**: 会社の社外向け情報発信として、AI関連ニュースを Instagram に毎日1本投稿する。
- **成功条件**:
  - 毎日1回、ニュース1本を「1枚画像＋解説文」で投稿できる。
  - 最初は人が承認してから投稿する。品質が安定したら、設定変更だけで完全自動に切り替えられる。
  - 誤った情報を公開しない。解説文には必ず出典を入れる。
  - パソコンの電源に関係なく、クラウドで動く。

## 2. 確定した方針（ユーザーが選んだもの）

| 項目 | 決定内容 |
|---|---|
| 発信先 | 社外 |
| 投稿の形 | 1日1回、1枚画像＋解説文（日本語） |
| 確認方式 | 最初は承認制。あとで完全自動に切り替える |
| 動かす場所 | GitHub Actions（クラウド） |
| 承認の方法 | GitHub の承認ボタン（Environment の Required reviewers） |
| リポジトリ | 公開（無料プランで承認ボタンを使うため） |
| 情報源 | 信頼できるサイトを指定する |
| アカウント | 現在は個人アカウント。プロアカウントへの切り替えが必要 |

## 3. 前提と制約

- 投稿には Meta 公式の「Instagram API with Instagram Login」を使う。
  - Instagram のプロアカウント（ビジネスまたはクリエイター）が必要。
  - **Facebook ページは不要**（2026-11-08 時点の Meta 公式情報に基づく）。
  - 必要な権限は `instagram_business_basic` と `instagram_business_content_publish`。
- 画像は**公開されたURL**に置く必要がある。形式は **JPEG のみ**。
- 認証用の鍵（トークン）は約60日で期限が切れる。期限前に更新する必要がある。更新できないまま期限が切れると、再認証が必要になる。
- 投稿数の上限は1日あたり50〜100件（公式の記載が揺れている）。1日1件なので影響はない。
- 自分のアカウントにだけ投稿する用途で、Meta のアプリ審査が必要かどうかは、実装時に画面で確認する。
- リポジトリが公開のため、プログラム・下書き・投稿履歴は誰でも見られる。鍵や API キーは GitHub の Secrets に置き、公開しない。

## 4. 全体の流れ

```
[毎朝 7:00 JST] 下書きジョブ
  1. ニュース収集   指定サイトのRSSから直近24時間の記事を取得
  2. 選定と文章づくり Claude が1本を選び、見出し・解説文・ハッシュタグ・出典を作成
  3. 画像づくり     見出しをテンプレート画像に文字として載せ、JPEGで保存
  4. 下書き保存     画像をリポジトリに保存（公開URLになる）。画像と文章を実行画面に表示
        ↓
[承認待ち] GitHub の Environment 承認
  5. あなたが内容を確認し、Approve を押す
        ↓
[承認後] 投稿ジョブ
  6. Instagram API で投稿 → 成功したら投稿履歴に記録
```

- 下書きジョブと投稿ジョブは別の係にする。
- 完全自動への切り替えは、Environment の Required reviewers を外すだけで行える。コードの修正は不要。
- 承認されなかった日は投稿を見送る。翌日に持ち越さない。

## 5. 部品

| 部品 | 役割 | 入力 → 出力 |
|---|---|---|
| 設定ファイル | 情報源サイトの一覧、投稿時間、文章のルールを持つ | — |
| ニュース収集 | RSS から記事を取得し、投稿済みの記事を除く | 設定、投稿履歴 → 候補記事の一覧 |
| 文章づくり | Claude API で1本を選び、日本語の見出し・解説文・ハッシュタグ・出典を作る | 候補記事 → 下書きの文章 |
| 画像づくり | テンプレート画像に見出しを載せる。日本語フォントは同梱する（ライセンスが自由なもの） | 見出し → JPEG画像 |
| 下書き保存 | 画像と文章をリポジトリに保存し、実行画面に要約を表示する | 画像、文章 → 保存済み下書き |
| 投稿 | Instagram API でメディアを作成し、公開する | 下書き → 投稿ID |
| トークン更新 | 約60日で切れる鍵を、定期的に更新する | 現在の鍵 → 新しい鍵 |
| 投稿履歴 | 投稿済みの記事URLを記録し、二重投稿を防ぐ | — |

- 実装言語は Python とする。
- Claude のモデルは設定で変更できるようにする（初期値は Claude Sonnet 5.5）。

## 6. 内容を守るためのルール（社外発信のため）

- 解説文には必ず出典（元記事の名前とURL）を入れる。
- 記事に書かれていない数字や事実を足さないよう、AIに指示する。
- 元記事の文章をそのまま写さず、要約して書き直す。
- 画像の文字は AI が描かず、プログラムで載せる。誤字や文字化けを防ぐ。

## 7. 失敗したときの動き

| 状況 | 動き |
|---|---|
| ニュースが取れない、候補がない | その日は下書きを作らない。GitHub に失敗が通知される |
| 文章づくりが失敗した | その日は見送る。無理に出さない |
| 投稿が失敗した | 承認済みでも投稿されず、失敗が通知される。履歴には記録しない |
| トークン更新が失敗した | 期限切れの前に通知する |
| 同じ記事を再度選んだ | 投稿履歴と照合して除外する |

## 8. 動作確認の進め方

1. **練習モード**: 実際には投稿せず、下書きの画像と文章だけを作って確認する。
2. 画像のURLを Instagram が取得できるか、1回だけ本番で投稿して確認する。
3. 数日間は承認制で運用し、内容の品質を見る。
4. 安定したら、完全自動への切り替えを検討する。

## 9. 実装の最初にやること

- 候補サイトの RSS が使えるかを確認し、情報源の一覧をユーザーが承認する。
- 社外発信用に、個人アカウントのままにするか、会社用アカウントを新しく作るかを確認する。

## 10. ユーザーに準備していただくもの

1. Instagram をプロアカウントに切り替える（無料、数分）
2. Meta の開発者サイトでアプリを登録し、投稿用の鍵を取得する
3. Claude の利用キー（API キー）を取得する
4. GitHub アカウントを用意する
5. GitHub の個人用アクセストークン（Secrets を書き換える権限のみ）を作る。投稿用トークンの自動更新に使う（標準の権限では Secrets を書き換えられないため）

手順は実装の段階で、画面を見ながら番号付きで案内する。

## 11. 対象外（今回やらないこと）

- コメントの自動返信
